# 0.3.1 — Ember Sky corrections

This release completes the remaining implementation work identified after
0.3.0 was published. The real GitLab provider acceptance job remains deferred
in #25; automated component tests do not claim to replace it.

- Wrapped receipts record their execution mode and canonical command argv.
  Recipients recompute declared inputs and outputs without `attest.yaml`.
  Wrapped execution applies the native local input guard and checks inputs
  again after the build, preserving a failed build's original exit code.
- CI integrations expose independent build, evidence, verification and
  publication results, with explicit required/optional evidence policy.
  GitLab package publication is confirmed before its final machine report.
  `attest timestamp` attaches time evidence to an existing signature without
  re-signing or accessing a private key.
- Workflow verdicts include the recipient's exact identity requirements,
  verified claims and separate receipt-producer/workflow/artifact-signer roles.
- Evidence packages include referenced capsule manifests and causal events.
  Recipient policy controls completeness; missing proofs are named explicitly,
  and required missing or altered proofs prevent acceptance offline.
- SLSA v2 exports retain the exact original signed receipt and timestamp,
  original signer, optional workflow proof and public trust context. Subjects
  identify actual file bytes. Builder identity is a verified workflow or an
  explicit unverified marker. Import separately verifies the DSSE envelope
  and original receipt against recipient-controlled trust. Re-signing cannot
  authorize a revoked or unknown original signer. Multiple envelope signatures
  are explicitly refused by the single-signature importer.

Existing receipt signatures remain valid. New optional execution metadata is
signed. Evidence writers use `attest-evidence/v2`; v1 packages remain readable
with the new completeness checks. Older verifiers refuse v2 rather than
silently omitting these checks. New SLSA exports use the versioned
[public build-type definition](../specifications/attest-pipeline-v2.md);
legacy imports explicitly report their narrower verification semantics.

Acceptance and adversarial coverage include transferred workspaces, disabled
network verification, missing/substituted proofs, fresh GitHub workflow identity,
original/DSSE signer separation, and removal of security checks by the mutation
gate. Release publication remains subject to the normal signed-tag, protected
CI, artifact-signature, provenance and independent verification gates.
